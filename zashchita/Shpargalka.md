# Шпаргалка к защите (для тебя)

База: **clinic_db** · программа: **pgAdmin**

**Пароли:**
- учебные логины `u_admin` / `u_registrar` / `u_doctor` → пароль `ClinicDemo1!`
- пользователь `postgres` → пароль, который задали при установке PostgreSQL (не путать)

Перед защитой лучше поднять **чистый эталон** или пересобрать базу — после репетиций слоты могут быть уже заняты.

На защите открывай Query Tool и копируй запросы **по одному**. Перед новым запросом очищай окно.

---

## Как открыть запросы в pgAdmin

1. Слева найди сервер → базу **clinic_db**.  
2. Правой кнопкой по **clinic_db** → **Query Tool**.  
3. Вставь запрос → кнопка ▶ (или F5).  
4. Смотри результат внизу во вкладке **Data Output**.  
5. Перед новым запросом **очисти** окно (выдели всё → Delete), иначе можешь случайно выполнить старый текст.

> Я сделала базу данных для поликлиники. В ней есть картотека пациентов, врачи и медсёстры, расписание приёма, посещения с диагнозами и назначениями. Есть разделение прав (админ, регистратура, врач) и резервное копирование. Работаю через pgAdmin, без сайта.

## Блок 1. Кто работает в поликлинике

### Что сказать

> В таблице сотрудников есть врачи и медсёстры. На приём записывают только к врачам. Медсестра тоже в штате, но слотов у неё нет.

### Запрос

```sql
SELECT id, full_name, staff_kind, specialty, department, office
FROM staff
ORDER BY id;
```

### Что на экране / зачем

Строки штата: `doctor` — врач, `nurse` — медсестра. Показываешь, что сотрудники учтены и на приём идут только врачи.

## Блок 2. Свободное время к врачу

### Что сказать

> Это поиск свободных слотов к нужному специалисту — задача из методички.

### Запрос

```sql
SELECT appointment_id, doctor_name, specialty, start_at
FROM v_free_slots_by_specialty
WHERE specialty = 'терапевт'
ORDER BY start_at;
```

### Что на экране / зачем

Свободное время к терапевту. Это отчёт (VIEW) из методички — поиск свободных слотов.  
Если пусто — слоты уже заняли на репетиции; покажи все свободные:

```sql
SELECT * FROM v_free_slots_by_specialty ORDER BY specialty, start_at;
```

## Блок 3. Записать пациента на приём

### Что сказать

> Регистратура берёт свободный слот и ставит пациента. Статус меняется на «занят».

### Запрос

```sql
UPDATE appointments
SET status = 'booked',
    patient_id = 2
WHERE id = (
    SELECT appointment_id
    FROM v_free_slots_by_specialty
    WHERE specialty = 'терапевт'
    ORDER BY start_at
    LIMIT 1
)
RETURNING id, status, patient_id;
```

### Что на экране / зачем

Одна строка: `booked` и `patient_id = 2`. Показываешь запись на приём.

### Если 0 rows

Свободных слотов к терапевту не осталось — запиши любой свободный:

```sql
UPDATE appointments
SET status = 'booked',
    patient_id = 2
WHERE id = (
    SELECT appointment_id
    FROM v_free_slots_by_specialty
    ORDER BY start_at
    LIMIT 1
)
RETURNING id, status, patient_id;
```

## Блок 7. Права доступа (важно!)

### Что сказать

> Права разделены по ролям. Врач не может менять штат сотрудников — только смотреть пациентов и вести приём.

### Запрос (сначала этот — должна быть ОШИБКА, так и задумано)

```sql
SET ROLE clinic_doctor;
UPDATE staff SET office = '999' WHERE id = 1;
```

### Что увидишь

Красная ошибка: **нет доступа к таблице staff**.  
На защите скажи: «Это нормально — система не даёт врачу менять штат.»

### Обязательно после ошибки верни обычные права

```sql
RESET ROLE;
```

Без `RESET ROLE` следующие запросы могут вести себя странно.

### Зачем этот блок

Показать «групповые политики» / разграничение доступа из методички.

## Если препод спросит

| Вопрос | Короткий ответ |
|--------|----------------|
| Почему запись и визит — разные таблицы? | Запись — это план («когда придёт»). Визит — факт осмотра с диагнозом. Можно записаться и не прийти, можно прийти без записи. |
| Зачем медсестра в базе? | Она сотрудник поликлиники. На приём пишут только к врачам. |
| Что такое VIEW? | Готовый сохранённый запрос-отчёт. Удобно показывать слоты, карту, нагрузку, льготы. |
| Что такое МКБ-10? | Код диагноза. В базе хранится код; полный справочник всех болезней в курсовую не загружала. |
| Как защищены данные? | Роли PostgreSQL (админ / регистратура / врач) + бэкап. Для реальных данных в работе описано шифрование и соль. |
| Почему ошибка на UPDATE staff? | Я специально показала роль врача — ему нельзя менять штат. |
